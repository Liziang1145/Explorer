## 架构

每通道各一个CTU CAN 2.2实例，复用现有MIT头声明源码快照（不升级原CAN2）；APB接口由新控制模块驱动。旧源码许可证和来源哈希随交付提供，不使用AMD付费CAN IP。

新模块每通道一个AXI-Lite从接口，初拟0x80310000和0x80320000，各64KiB，最终由Vivado地址导出确认。每模块0x4000..0x4FFF为受所有权保护的CTU原生寄存器窗；其余为控制、命令、事件与完整20槽反馈（251..256、261..266、2A1..2A8）。原测量模块原样保留，监测真实物理RX/TX。

每通道三个运行所有者：PS_GENERIC=0、PL_GENERIC=1、PL_ARM=2；ISOLATED=3只输出隐性电平。PS/PL TX硬件MUX只有一个输出驱动；非所有者CAN控制器RX置隐性，避免非所有者内部ACK/错误状态被误认为物理输出。原被动观察器仍看真实引脚。

通用PL路径使用真实CTU SocketCAN驱动；机械臂路径独占同一CTU核心，由硬件队列产生帧。通用与专用不同时写核心；通用TX完成仅由CTU真实完成状态/IRQ判断。经典CAN标准/扩展/RTR能力据实际仿真公布；公开接口只承诺Classic CAN，不默认启用FD。

## 切换与恢复

PREPARE -> DRAIN -> ISOLATED/RESET -> READY -> COMMIT。每次请求递增generation，Linux明确停止新目标、清PS/通用发送队列后回写该generation确认。硬件等待总线连续隐性至少11 bit、当前TX隐性、内部事务已停止，才断开/复位PL核心。COMMIT还需新generation、目标初始化完成和空闲；回读确认。RELEASE等价于准备PS再提交，不能跳过确认。

故障停止后续目标，撤销专用队列，终止待发/重试并在合法边界隔离；不自动发送471或失能，不把通信回退等同于机械急停。AUTO默认关闭。开启后故障发出FALLBACK_PS请求/IRQ，Linux自动清旧命令并提交PS；PS运行后定时提出RETRY_PL，Linux可自动准备/恢复。重试间隔和最大次数开放，0次数表示长期无限，最小间隔限制防抖。超时未完成握手不擅自切线。

## 机械臂队列

新控制ABI使用独立MAGIC/BUILD/CAPS。保留128B wire-v1字段位置和CRC32C规则，schema/version明确区分；kind1位置5帧、kind2夹爪1帧、kind3原子入队的位置+夹爪6帧（151,151,155,156,157,159）。PS已完成限位/符号/单位转换，PL不重复做。两通道独立64条队列，200Hz各消费最多一组。每组内部不混入另一组或通用发送。

过期未开始组整组丢弃；CAN多帧不能提供总线上的事务回滚：若仲裁/错误使已开始组超过截止时间，停止剩余帧、报告已完成帧数及部分组故障，不谎称整组原子发送。禁止重复播放旧组。

事件区分accepted/scheduled/实际SOF/真实CTU完成/失败/组结果；只有专用发送可附真实seq/trace。接收反馈无因果seq。所有事件丢失有计数，不能以候选事件冒充物理完成。
