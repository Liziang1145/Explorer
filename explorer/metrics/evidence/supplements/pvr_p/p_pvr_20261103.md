本项目的系统特色适合表述为：**以 VR 遥操作保留人的观察和操作能力，以场景证据支持本地模型辅助任务生成，以确定性导航和反馈执行任务**。基础 SLAM、YOLO、Pure Pursuit、场景图和大模型任务规划不是本项目首创；贡献集中在真实硬件上的组织、适配、证据约束、异步产品链和人机协作。

## 2. 当前生产链路：输入—处理—产物—任务

```text
环境：LiDAR + IMU + RGB-D + 鱼眼
  │
  ├─ 独立原始录制：雷达、IMU、RGB-D、鱼眼分别落盘
  │
  ├─ 原车 FAST-LIO 在线几何 / 位姿
  │    ├─ 10 cm 导航几何 → 地面 / 障碍 / 未知 / 历史通过证据
  │    │    → 导航栅格 + 定位参考 + 矩形路线 → 连续 RC 跟踪
  │    └─ 同场 RGB-D / YOLO + 同源位姿
  │         → 对象 / 原图证据 / 邻近关系 → 当前场景上下文
  │
  └─ 原始数据离线密集重放 → RGB-D 优先、鱼眼补色
       → 全量密集彩色点云 + 5 cm 轻量彩色点云
       → 场景目录 / 全局粗图 / 近场精细块 → Quest 端渲染

人的意愿 → 工作台 / 本地千问 → 结构化任务草稿
           → 对象与证据校验 / 执行前提 / 确定性路线规划
           → 原导航执行接口 → AI PC 共享控制台 → KR260 → 底盘
           ← 到达 / 停车原因 / 实时位姿 / 底盘反馈 / 任务状态

人的动作 → Quest 眼镜与手柄 → 团队 VR 控制通路 → 机械臂 / 底盘
人的观察 ← 实时相机画面 + 可浏览的彩色点云场景
```

**必须使用的新口径：**导航不等全量彩色点云，也不再等离线密集重放。导航与语义采用同一份在线记录轨迹；全量彩色点云有独立的离线重放轨迹，二者不能未经配准就混用坐标或点编号。

新一轮建图结束后自动开始派生；导航校验通过后按现有场景切换联锁发布。切图不自动开车、不默认车辆仍在原点。每个地图把首个有效底盘中心 O 的平面位置记为 `(0,0)`，出发车头方向记为 `0°`，千问的 `origin` 随场景变化。
