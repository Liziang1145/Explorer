# 2026-10-13 模拟 VR 帧：AI PC → KR260 实机联调记录

## 范围

AI PC eno1 192.168.137.2 → 交换机 → KR260 eth1 192.168.137.224:54321/UDP。模拟报文采用原工程 whole_body_msg 的 78 字节二进制布局；mask 始终为 0。KR260 上仅运行 Python 接收/解码/ACK 程序，未连接 ROS、CAN、FPGA PL 或机械臂驱动。

## 环境核对

- AI PC 到 KR260 的路由为 dev eno1 src 192.168.137.2；ping 2/2 回复，RTT 约 0.21 ms。这只是 ICMP 网络连通性，不是控制链路延迟。
- KR260 eth1 为 192.168.137.224/24；开始前 54321/UDP 无监听程序。
- AI PC 和 KR260 分别运行 test_vr_frame.py + test_vr_sim_loopback.py：各 7 项通过。

## 原格式兼容性

在 AI PC 上用 g++ -std=c++20 编译 vr_cpp_compat.cpp，它调用原工程 WholeBodySender::Process。对计数 123、时间戳 456789、双手 X 位置 ±0.08 的同一输入，与 Python encode_sim_frame 比较，结果为：

    C++/Python byte-for-byte: MATCH bytes: 78

这是单个对照样例，不代表所有可能的浮点输入都已穷举验证。

## 跨设备收发

KR260 接收器监听 30 秒，AI PC 以 20 Hz、small-sine 模式发送 5 秒，计划帧数 100。

    AI PC: result sent=100 acked=100 unacked=0 ack_rate=100.0%
    KR260: result accepted=100 rejected=0 source_rejected=0 gaps=0 duplicate_or_old=0

KR260 实际打印了 cnt=0、19、39、59、79、99 的解码位置样例，mask 均为 0x0000，抓握量为 0。零附近的位置解码值约为 ±0.002，来自原 10-bit 量化，并非设备运动。

## 不能从这次测试推断的事情

- ACK 是 KR260 Python 程序回的，不是 FPGA、CAN 驱动或机械臂的执行回执。
- 只进行一次短测，不能据此声称长期稳定性或实时性。
- 两机时钟尚未同步，没有计算单向延迟。
- 原 C++ CRC::CalculateBits(data, 76, ...) 的 76 是位数，只有前 76 位受 CRC 保护；后续控制字段未受完整性保护。测试模拟器故意保持兼容，不能直接用作安全控制协议。
- 没有真实 VR 设备输入、机械臂目标解算、限位、断联看门狗或急停验证。
